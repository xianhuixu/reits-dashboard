# 经营数据接入首版 · 2026-11-17

## 数据边界

- 用户提供 SQLite 库，经 `sqlite3 mode=ro` 导出；原库不进仓库。
- `research/operating-data.json` 为独立快照，含 SHA256、导入时间和来源标签。103 只基金、210 项资产；4,651 条标准化经营指标及 5,903 条基金层收入/EBITDA/可供分配金额（含不同报告期、单季/累计）。共 10,554 条，无重复全口径键。
- 默认报告期 2026Q3；经营/财务任一指标该期有记录 91 只。每次切换显示该期、该业态实际覆盖，不回填历史。
- 552 条经营记录的原层级标签与资产 ID 分类冲突。原标签保留；ALL 认作基金，具体项目必须匹配资产主表及所属基金。财务仅导出明确“基金层面”且 asset_id 为空或 ALL 的白名单指标；空ID规范为ALL并另存原值。
- 两表分别标识来源；不导出原文指标、估值收益率、杠杆字段、预测、原始同比及个人/登记信息。

## 页面

左侧新增「经营数据」主 tab。默认期为快照最新报告期。业态/报告期/指标/统计口径/基金搜索 → 覆盖信息卡 → 全宽原值表 → 按需展开历史原值表及项目明细。历史表没有合并不同 caliber；每行仍显示单位和税口径。不作跨口径排名或业态均值。

同店范围、期间完整性、税口径尚未逐项核实，因此不自动计算同比。较上年同期至当前期末窗口存在已知扩募纳入资产时标“含扩募，非同店”，否则标“不可比”，可点击查看原因。不将“未发现扩募”当成“同店已核实”。双方税口径未说明也不放行。

本版未绘制可能跨口径连线的趋势图，先提供历史原值表；图形和完整桌面/手机视觉验收待设计复核。待原公告复核统一标在页头。

## 性能与部署

进入经营页才 fetch 2.6 MB 原值 JSON，不增加首页数据请求。新增 JS/CSS/JSON 均放在既有递归镜像的 research/ 下，GitHub Pages 与现有 Cloudflare daily/tenders 复制路径均覆盖，无需修改工作流权限。口径规则同目录随站点发布；完整字段映射在 docs/operating-field-mapping.csv。

## 不变项

不修改 `data.json`、`advice.json`、原有 TTM、利差、IRR、宏观预警和配置结论。现有市场日期不代表经营数据自动更新；本快照没有自动续爬任务。

## 复现

`python3 scripts/export_operating_data.py /absolute/path/to/source.db`

`npm test` 包含经营模块的范围、缺失/零、百分比、不可比、扩募、部署路径和单季/半年口径测试。原导航滚动位置契约同步增加 ops。

### 阅读整改（2026-11-17）
- 基金对比按基金分页，每页 20 只；搜索及筛选重置第一页，覆盖数仍基于完整筛选范围，不因分页改变。
- 历史与项目明细直接插入所选基金行下，关闭后焦点返回触发按钮，一次只展开一只。
- 名称列在表内横滑时固定，手机名称下同时显示带单位核心值及展开按钮；明细自身横向滚动，不将长表撑出页面。
- 展开明细不再使用 `100vw` 限宽，改为相对对比表滚动容器的 `100cqw`，展开单元格 `max-width:0`，避免内外表最小宽度叠加后撑出整页横滑。
- 仅为代码整改及自动化校验，不代表已完成浏览器视觉验收；仍须桌面、手机实际检查。

### 业态核心指标与空值口径（2026-11-17）
- 「全部业态」默认「按业态核心指标」：交通为日均车流，能源为发电量，水务环保为营业收入，供热为供热面积，数据中心为上架率，租赁类为出租率；口径按该指标默认值选取，不把不同指标排在同一比较意义上。
- 用户若改选单一指标（例如在全部业态下看出租率），与业态不匹配的基金显示「该指标不适用」，有适用口径但无记录的显示「尚未披露」。零仍是已披露的 0，二者都不填零。
- 覆盖数按当期实际记录统计，不用上一期补齐；「不适用」单独计数，不计入「有值」。

### 同比提示（2026-11-17）
- 出租率、车流、电量等：税口径「不适用」不再标成「不可比」，在项目范围未复核完成前统一标「待核资产范围」，仍不算同比。
- 已确认窗口内扩募的，继续标「含扩募，非同店」。
- 平均租金、托管单价在含税口径未说明或未对齐时标「不可比」。客流/销售原始同比字段仍标「不可比」，不作为已核验同比列。
- 不把外部网站的可比样本直接当作已核验同店，也不写入横幅或利差。
