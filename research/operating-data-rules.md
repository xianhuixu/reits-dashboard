# REITs 经营数据接入禁则（给小七）

只读库审核日期：2026-11-17（Asia/Shanghai）。库文件未改。实现时一律用 `sqlite3` URI `mode=ro`。本清单只约束口径，不指定页面布局。

## 0. 总原则

1. 展示用标准化表，不用原文表。经营指标用 `ops_metric`，收入/可供分配用 `financials`（或与之完全一致的 `distcalc_item` 结果项），派息用 `distribution` 事件，行情用 `daily_quote`。
2. 禁止把 `ops_indicator_raw`、`project_perf`、`cost_breakdown` 的原始 `label` 直接画图或做横截面平均。
3. 任何同比、均值、排名，必须同时固定：指标、单位、caliber、tax_flag、层级、asset_id、报告期粒度。缺一项就不要算。
4. 库内没有的元数据不要补。尤其不要给 `market_valuation.valuation_yield` 标注来源或把它写成 IRR。
5. 金额先认单位再运算：`financials` / `ops_metric` 金额多为万元；`distribution.total_amount`、`extension_offer.raised_amount` 为元。

## 1. 覆盖与日期

- 基金主表 `reit_info` 103 只：存续 96、已获批未上市 7。未上市 6 只无资产（180107、181002、508038、508047、508606、508610）；508605 有资产但无 include_date。
- 508081.SH（华能reit）状态为「存续」但 `list_date` 为空，`asset.include_date='nan'`（文本）。比较日期前先排除非 ISO 值，否则会被当成晚于今天。
- 经营/财务最新报告期是 **2026Q3**，不是 2026A。2026-10 及以后上市的 6 只（180307、180505、180702、508095、508609，以及无上市日的 508081）没有 2026Q3 财务和 ops_metric，页面应显示「尚未披露」而不是 0。
- 行情与估值日最大为 **2026-11-13**，没有晚于 2026-11-17 的交易数据。
- 真正晚于 2026-11-17 的日历日期只有：
  - `distribution`：除息 2026-11-18（1 笔）、派息 2026-11-18 至 2026-11-23（5 笔）——已宣布、尚未到付息日，可标「已宣告未发放」，不是预测。
  - `concession_end.end_date`：2029-12-09 至 2058-10-31（41 行）——合同到期，应保留。
  - `forecast.year=2027`（71 条）——预测，不是已实现。
- 不要把报告期标签 `2026Q3`、`2026H1` 用字符串去和 `2026-11-17` 比大小（`'2026Q3' > '2026-11-17'` 为真，会误伤）。

## 2. 层级：不要相信 `level`，以 `asset_id` 为准

- 基金层：`ops_metric.asset_id='ALL'`。
- 项目层：`asset_id` 能在 `asset.asset_id` 里找到（形如 `180101.SZ-A01`）。
- 反例：297 行 `level='基金层面'` 但 `asset_id` 是具体项目；255 行 `level='项目'` 但 `asset_id='ALL'`（可出租/已出租面积等）。540 个基金期同时有 ALL 和项目行。
- `financials` 的 `基金层面` 与 `项目公司层面` 禁止加总或混排成同一列。

## 3. 报告期粒度：禁止 Q / H1 / A 混算

- `financials` 中，收入、EBITDA、净利润、OCF 的「年初至今」**只出现在 A 和 H1**；季报只有「本期」，且「本期」是单季（180101 等可验证：H1≈Q1+Q2）。
- H1 的「本期」等于上半年合计，不是 Q2。做 TTM 或同比时：
  - 允许：2026Q3 本期 vs 2025Q3 本期。
  - 禁止：把 2026Q3 + 2026H1 误标为单季、2026Q3 vs 2026H1 直接同比、把 A 当 Q4。同范围同单位且Q3确为单季时，H1+Q3 可构造前三季度累计，但须标明派生口径。
- A 并不总是等于四个单季之和（131 对中 51 对差额 ≥2 万元，最大超过 1000 万元）。不要用四季反推年报来填空。
- `ops_metric.caliber`：期末 / 期间 / 期间平均 / 期间累计。出租率、收缴率、通行费都出现过多种 caliber，不能丢掉 caliber 去重。
- 期间累计 ≠ 单季。例：`508001.SH` 2021Q4 `toll_revenue` 期间 19474.12 万元，期间累计 78822.45 万元。

## 4. 同比只能在这些条件下做

必须同时满足：

1. 同一 `metric`、同一 `unit`、同一 `caliber`、同一 `tax_flag`（含税口径须已确认；双方均未说明不能证明可比）、同一 `asset_id`。
2. 报告期类型相同（Q3 对 Q3，H1 对 H1，A 对 A）。
3. 两个报告期的时间长度相同。上市首年可能不足 12 个月（见 `forecast.start_month`，大量为 4–12、7–12、10–12 月），不能拿残缺年报对完整年报。
4. **扩募同店**：基金层合计在扩募生效日后不可直接同比。用 `asset.include_type='扩募'` 的 `include_date`，或 `extension_offer.effective_date` / `share_event.event_type='扩募'`（10 只基金、18 个扩募资产）。例：`180101.SZ` 2023-06-16 并入光明加速器二期后，收入从 2022A 11310 万元升至 2023A 18078 万元，不是同店。
5. 同店算法：只对 `include_date` 早于较早期初、且期间未退出的项目加总；`exit_date` 目前全空，不代表没有退出；还需核实项目持续在池及合并范围，不能只据日期认定同店。
6. 禁止使用 `ops_indicator_raw.yoy`。该列多数是 `(cur/prev-1)*100`，但出租率/收缴率里至少 70 条是百分点差（`508021.SH` 2025Q3 出租率 96.59 vs 90.80，yoy=5.79 不是 6.38）；`prev=0` 时出现 2,082,660.67。
7. `footfall_yoy`、`sales_yoy` 已经是同比（单位 `%`），禁止再算一次同比。
8. 平均租金 15 只基金出现含税 / 不含税 / 未说明切换。反例：`508078.SH` 2025Q1 含税 39.24 元/㎡/月 → 2025Q2 不含税 36.50，不能解释为租金下跌。
9. `treatment_volume` 只有 2 只基金且不是同一类业务（508006 水务千万吨级 vs 180801 生物质二十万吨级），禁止业态平均或排名。

## 5. 派息 TTM

- 不要「最近 4 条派息相加」。各基金一年 1–5 次，所属期类型混用。
- `income_period='2025'` **不等于 2025 全年**。2025 年有 53 只基金同时存在 `2025` 与 `2025H1`/`2025Qn`，此时 `2025` 是剩余所属期。
- 收益所属期口径：只有官方区间明确才能映射月份拼接，YYYY标签含义不清时停止自动计算。除息日口径的过去365日派息率是另一指标，可逐笔核验去重后按除息日加总，不应把所属期标签疑似重叠直接认作重复派息。
- 截至 2026-11-17，若机械将YYYY解释为全年，窗口2025-10至2026-09仅2只无重叠盖满、29只疑似重叠、51只缺口。这是标签解析诊断，不证明真实现金分派重叠或缺失；不得据此撤掉现有核验后的除息日TTM。
- `financials.actual_distribution` / `dps_actual` 不得作为已派息主口径：2025A 至少 8 只账面为 0 但事件表有金额；`508066.SH` 2023A `dps_actual=6.2` 与事件表（约 0.57 元/份）冲突。
- `dps_pretax` 已标明税前，不要再假设含税或再扣一次税（库内无税率）。

## 6. 估值收益率：禁止自动认作 IRR

- `market_valuation` 没有 unit、source、method、caliber、tax_flag 字段，来源不能从库内推断。
- `valuation_yield` 数值是小数（最新一日中位 6.65%，全样本 3.4%–24.5%），**不得写成 IRR、披露 IRR、资本化率或分派率**。
- 证据：它与过去 365 日已派 `dps_pretax/close` 大多对不上（82 只里仅 11 只差距小于 50bp；`508001.SH` 6.22% vs 滚动已派 16.69%）。经营权最新均值 7.15%，也到不了已讨论过的披露 IRR 量级。
- 在来源核查清楚之前，该字段不要进利差图、不要进横幅、不要和期限匹配国债相减。
- 同期不要误用：`valuation_price` 与 `close_price` 在 54328/55032 行相等；`daily_quote` 的 `cbc_valuation`、`cs_valuation` 全空；`remaining_years` 不能代替 `concession_end`。

## 7. 必须改名或隐藏的字段

| 字段 | 原因 | 处理 |
|---|---|---|
| `financials.leverage_ratio` | 实为总资产/净资产，408/408 能对上，值域 1.01–1.39 倍 | 改名「权益乘数」，禁止叫杠杆率/LTV |
| `financials.actual_distribution`、`dps_actual` | 与派息事件冲突，存在 0 和 6.2 异常 | 不进主图 |
| `market_valuation.valuation_yield` | 无来源，非 IRR | 不进利差/横幅 |
| `market_valuation.remaining_years` | 口径不明，与到期日、term_years 对不齐 | 特许到期用 `concession_end` |
| `ops_indicator_raw.yoy` | 相对变化与百分点差混用，还有除零爆值 | 不用 |
| `forecast.*` | 预测，首年常不足 12 个月 | 与实际分开展示，对齐起止月 |
| `footfall_yoy` / `sales_yoy` | 已是同比 | 禁止再同比 |
| `expansion_status.status` | 文本脏（无/已完成/自/-） | 扩募用 extension_offer / asset / share_event |

## 8. 建议的第一批接入（页面可用）

优先，且默认基金层 `asset_id='ALL'` 或 `level='基金层面'`（财务）：

- 出租率（期末，小数×100）
- 平均租金（期间平均，必须带 tax_flag 标签）
- 收缴率（展示时写清是期末还是期间）
- WALE（年末/期末，年）
- 日均车流（车次/日）
- 发电量 / 上网电量 / 结算电量（万kWh，期间）
- 营业收入、EBITDA、可供分配金额（本期，万元，单季）
- 派息事件（税前每份 + 派息日），不做自动 TTM
- 行情收盘价

项目层作为下钻，不要默认和基金层并排平均。

## 9. 缺的元数据（库内没有，不要编）

- 所有估值字段的来源、方法、单位、估值机构、估值日（相对净值的「最新」也无对应报告期）。
- 财务与通行费等的含税/不含税（财务 tax_flag 几乎全是「未说明」或空）。
- 利用小时、处理量是否年累计。
- `income_period='YYYY'` 在与分期并存时的官方所属区间。
- `debt_balance` 是否有息、是否含股东借款。
- `concession_end.hits` 的含义；一码多到期日如何取主到期。
- `forecast` 的单位、假设日、披露来源。
- 原始 label 的标准映射表（986 个标签未编码）。
- 资产退出：`exit_date` 全空，不能据此判断已处置资产。
